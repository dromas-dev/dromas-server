# Security

**The protocol is designed against this server.** Clients treat it as possibly hostile: a mailbox checks every signature, prekey and revocation itself, and believes nothing a server says. So what protects a message is not in this repo. It is in [dromas-client](https://github.com/dromas-dev/dromas-client), whose [`SECURITY.md`](https://github.com/dromas-dev/dromas-client/blob/main/SECURITY.md) maps each promise a mailbox is given to the code and tests that hold it. This file covers what the server itself must get right, and how to report where it does not.

## Supported versions

**Before v1, and only the latest release and the latest commit on `main` are supported.** A fix is a commit on `main`, released as the next patch. The major version is the protocol's, shared with the client, so both are 0.x until the protocol is frozen, and v1 together; minors and patches are each repo's own.

## Reporting a vulnerability

**Report it privately, with GitHub's private vulnerability reporting:** the **Report a vulnerability** button under this repo's Security tab, or from a terminal:

```sh
gh api repos/dromas-dev/dromas-server/security-advisories/reports \
  -f summary='…' -f description='…'
```

- **Here:** this server, and dromas.dev as it is run.
- **The protocol, the clients or the vectors:** dromas-client, by the same route. Not sure which? Either one.
- **How to write one, what is not a vulnerability, and what happens next:** dromas-client's [`SECURITY.md`](https://github.com/dromas-dev/dromas-client/blob/main/SECURITY.md). It applies here as written. A way around a limit that `LIMITS.md` does not already list as a known weakness is a vulnerability.

## What this server must still get right

| The claim | Held by |
|---|---|
| **It never holds a private key and never sees plaintext;** it stores ciphertext and a mailbox's public documents | `AGENTS.md` § Invariants; what it stores and for how long is the spec's §13, and how, `ARCHITECTURE.md` § Storage |
| **It holds no signature on a message and issues no credential:** a mailbox proves itself with a pass it signs, which says who is calling and nothing of what the call does | `internal/server/pass.go`; `server_test.go`, `keytype_test.go`, `clock_test.go` |
| **A pass is checked in three steps, in a fixed order:** the certificate against the mailbox's current one, the working key's signature, then the identity's signature on the certificate | `checkPass`; `ARCHITECTURE.md` § The pass check |
| **A pass is taken only for a name of the server's own,** the request's `Host` written as an origin is, and a call with two `Authorization` lines carries none | `serverName` and `authorization` in `internal/server/pass.go`; `TestAPassIsForOneServer`, `TestTheServerReadsItsHostAsAnOrigin`, `TestTwoAuthorizationLinesAreNoPass` |
| **A pass is remembered by the one form a client writes it, its signature as a verifier reads it,** so the same pass written in another form the server reads, its signature's armor and SSHSIG blob included, costs no second signature check, and is taken from memory past its address's count | `passCheck` in `internal/server/pass.go`, `protocol.Pass.Authorization`; `TestMissesPerIP`, `TestARespelledPassCostsNoSecondCheck` |
| **`If-None-Match` names a page only by that page's own tag, or by `*` as the whole value,** read as RFC 9110 §13.1.2 has a server evaluate it, so a tag that holds a comma or a `*`, which a mailbox may be handed and keep, makes no other page `304` | `list` and `listTag` in `internal/server/messages.go`, `precondition` and `conditions`, `protocol.IfNoneMatch`; `TestAFirstPageIsNotModifiedWhileUnchanged`, `TestAPlantedTagHidesNoMessageAtAnHonestServer`, `TestAMessageHiddenByAPlantedTagIsNotLost` |
| **No ACL is the last a mailbox can write:** an ACL carries no number its writer chooses, a `PUT` without `If-Match` replaces whatever is held, and one whose `If-Match` is false changes nothing, the `If-Match` held to the ACL its write replaces, so what a leaked pass writes there lasts until the owner writes the next (the client repo's issue #360) | `putACL` in `internal/server/acl.go`; `TestAnACLsIfMatch`, `TestAnACLsIfMatchIsHeldToTheACLItsWriteReplaces`, `TestACLRoute` |
| **What memory holds of an address never goes back to before a revocation this process has seen, not even for a moment,** by its own write or the stream (another process sees one by the stream, a second or two later): each write is counted and applied in one step, and a copy read before a write counted since its read began is never put where memory does not already hold the address, every write since applied to it; a lookup that joins such a read reads again; two copies of an address merge to every revocation either holds, a stored list that does not parse kept so that its use fails closed, and a record never moves back to an older one, ordered by when its mailbox registered, then by its rev; every read that fills memory is strongly consistent; a write of its own whose outcome is unknown, a revocation among them, makes the process forget the address, so that its next use reads the record; and an item the stream brings that does not read, of any kind, is taken as gone | `recCache.write` and `recCache.fill` in `internal/server/boxcache.go`, `mergeViews` and `version` in `store.go`, `Memory.Mailbox`, `Memory.write` and `Memory.apply` in `memory.go`, `Server.lookup`; `TestEveryOrderOfAFillAndAWrite`, `TestALookupJoinedToAReadBegunBeforeARevocationReadsAgain`, `TestARevocationWhoseAnswerWasLostIsInTheNextPassCheck`, `TestAWriteThatMayHaveBeenAppliedForgetsItsAddress`, `TestEveryWriteOfTheBackendReachesMemoryByItsOutcome`, `TestAnItemThatDoesNotReadIsGoneWhateverItsKind`, `TestARegistrationAfterTheTTLsRemovalIsNewerThanTheRemovedRecord`, `boxcache_test.go` (the races on DynamoDB) |
| **Every request is counted before anything is done for it:** each handler is put on its router through one gate, where a call that is not its mailbox's (a pass this process has checked, of a mailbox live in its memory, on a route that takes that mailbox's pass) spends its address's flood budget, so a new pass is parsed and its signatures checked only after a count; the read of a mailbox takes no pass, and reads none whatever it carries; and a request's head is read only to what the longest call needs | `mount`, `gate` and `HTTPServer` in `internal/server/server.go`; `TestEveryRequestIsCountedBeforeAnythingIsDone`, `TestLookupsArePaidByTheirCaller`, `TestAServerNotReadyCountsFirst`, `TestOptionsStarIsCounted`, `TestANewPassSpendsItsAddresssFloodBudget`, `TestTheHeadIsReadToWhatTheLongestCallNeeds` |
| **No call that costs the server is free, and a stranger never spends a mailbox's budget:** every limit, who pays it, when it is taken, and its known weaknesses | `LIMITS.md`; `budgets_test.go`, `quotas_test.go`, `limits_test.go`, `marks_test.go` |
| **Every call answers the state of the mailbox whose pass it carries, and a read the state of the mailbox it reads, before it judges any pass,** with the codes `PROTOCOL.md` §11.4 gives (the order of refusals) | `owner` and `sender` in `internal/server/pass.go`, `register` and `prekey` in `mailboxes.go`; `TestEveryCallAboutAMailboxAnswersItsStateBeforeItsPass` |
| **What could change nothing is answered from what is kept, never refused by a count of what it would make new:** an identical retry of a registration or a renewal, a revocation the server holds already, a send of bytes its recipient holds unacked, from any sender (`PROTOCOL.md` §11.4, the order of refusals) | `registered`, `prekey` and `revoke` in `internal/server/mailboxes.go`, `deliver` in `send.go`; `TestARetryIsAnsweredFromWhatIsKeptWhateverItWouldMakeNew` |
| **A call's preconditions are evaluated once its target's state is known and before the call acts, and a false one does nothing but count as a call of its route** (`PROTOCOL.md` §11.4, the order of refusals) | `precondition` and `conditions` in `internal/server/conditions.go`; `TestAFalsePreconditionIsACallThatDoesNothingElse` (`preconditions_test.go`), on every route of `routes()` |
| **The operator's commands are reached only through a Unix socket the server makes 0600 from its bind on, whatever the umask, never through the API,** and nothing logs which address or mailbox one acted on or listed | `internal/server/admin.go`, `cmd/dromas-server/limits.go`, `cmd/dromas-server/socket_unix.go`; `admin_test.go`, `quotas_test.go`, `cmd/dromas-server/limits_test.go`, `cmd/dromas-server/limits_unix_test.go` |
| **The metrics are on a listener of their own, never the API's, and carry no value a caller chose:** no address, IP, mailbox, message id or path as sent | `internal/server/metrics.go`, `cmd/dromas-server/main.go`; `metrics_test.go` (`TestMetricsCarryNoCallerValue`) |
| **No log line carries an address or a message id, and nothing a caller sends is written in the access log:** each run of 64 or more hex characters in any line, a store's error, the AWS SDK's own lines and a stream follower's panic included, is written as a short hash of itself; the access line is the route's pattern with each wildcard's value hashed whole, a path no route answered its length, and a method its length unless it is of the IANA method registry's form, capitals and hyphens, and no longer than the longest method it lists, too short to hold a run of hex the redaction reads | `redact`, `Redacting`, `AWSLogger`, `loggedPath` and `loggedMethod` in `internal/server/server.go`, `feed.run`, `cmd/dromas-server/main.go`; `TestNoLogLineCarriesAnAddress`, `TestTheAccessLogWritesWhatTheRoutersMatched`, `TestTheAWSSDKsLinesAreRedacted`, `TestServeAndAccountWriteTheSDKsLinesRedacted` (`cmd/dromas-server`), `TestAFollowersPanicIsLoggedRedactedAndEndsTheProcess` |
| **Keyed hashing is HMAC or HKDF only,** never `hash(secret ‖ …)` | `internal/server/index.go` |
| **An adopt key is kept only as its SHA-256,** so a copy of the accounts table holds no key, and one that is not this server's is refused before anything is written | `internal/server/adoptkey.go`, `accounts.go`, `dynamo_accounts.go`; `TestAnAdoptKeyIsKeptAsItsHash`, `TestAccounts` |
| **Every error is RFC 9457 Problem Details, its `type` its code's own, and every value in its `detail` is a member of its own,** so no client needs to show a server's words | `problem_test.go`; `api/apitest`, which every test server is wrapped in, fails a `type` that is not its `code`'s; the spec's §11.3 |
| **Nothing that puts what a sender chose beside a mailbox's own values is compressed,** a list above all (BREACH): only a mailbox's read, which is public, is gzipped, and only for a request that takes gzip; a site's answer is its web server's, passed on as it came | `internal/server/compress.go`; `TestNoOtherAnswerIsGzipped`, `TestAMailboxsReadIsGzippedWhenTaken`, `TestASitesAnswerIsCompressedOnlyByTheSite`; `api/apitest` fails gzip on an answer the API's description does not let a server compress, or to a request that did not take it |
| **Revocation is kept as the identity signed it, mailbox or none,** and every `410 revoked` carries the record held where the call has it at hand; a registration is held to it | `revokedWith` in `internal/server/server.go`; `revocation_test.go`, `revokedcerts_test.go`, `expiry_test.go`, `TestEvery410CarriesTheRecord` |
| **Every error is tested over raw HTTP against the spec's status map,** and both clients run end to end against the real server | `internal/server/*_test.go`, each test server wrapped in the client repo's `api/apitest`, `e2e_test.go`; `test/interop.sh` for the shell client |
| **A release is built by this repo's workflow from a tag its maintainer signed, after its tests pass on that commit:** no tag that is unannotated, unsigned, or signed by a key `.github/allowed_signers` does not name is built (`git verify-tag`), and the whole of CI runs on the tagged commit before the build; every file the release's `checksums.txt` names, the SBOM of each archive among them, carries an attestation of the build that names the tag, the commit and the workflow, and `checksums.txt` is signed with cosign by that workflow's identity; the release's image, `ghcr.io/dromas-dev/dromas-server:<version>`, holds the archives' very binary (GoReleaser's `dockers_v2`), with an attestation of the build and an attested SPDX SBOM by the same workflow (the release's notes have the commands). `allowed_signers` and the workflows are read from the tagged commit; only an org admin can make, move or delete a `v*` tag, and a release is immutable. Each published release and its image are checked by those commands, and the release is built again from its tag, each archive compared | `.github/workflows/release.yml`'s jobs `tag`, `ci`, `verify` and `rebuild`, on every release; the attestations and the signature, by `gh` and `cosign` themselves; the tag ruleset `release tags: made by an org admin only, never moved or deleted` and immutable releases, settings of the repo that no test reads (`gh api repos/dromas-dev/dromas-server/rulesets`, `…/immutable-releases`) |
